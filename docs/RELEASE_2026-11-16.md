## Mod de lansare și recuperare

Imaginea semnată a fost lansată direct de pe VPS prin `scripts/deploy.sh`, cu
tagul, digestul și SHA-ul exact al buildului verificat. Nu au fost ocolite
verificarea semnăturii Sigstore, verificarea identității workflow-ului, limita
de vechime gVisor sau verificările de readiness/rollback.

Pe host lipsea `cosign`; a fost instalat `v3.1.4` din release-ul oficial, după
verificarea checksumului publicat. Rularea a folosit autentificare temporară
pentru registry; copia temporară a credentialelor a fost eliminată după deploy.
Cheile SSH și secretele GitHub Actions existente nu au fost modificate.

Imaginea anterioară este păstrată ca `pdfeditor:rollback` și suplimentar ca
`pdfeditor:pre-release-61f50b7`:
`sha256:d1f0dde281cbff7eda4180cd5259e28bc8e2b7ed065ef81cd3ae76b126d89747`.
Au fost verificate înainte de lansare ramurile de eșec ale scriptului și
procedura de rollback. Nu a fost necesară revenirea la imaginea veche.

Nu există migrări noi în această versiune; verificarea schemei înainte de
lansare a trecut. PostgreSQL, PgBouncer și Redis au rămas în containerele
existente. Scriptul a recreat serviciile aplicației și serviciile auxiliare ale
acestui proiect conform configurației Compose; ClamAV a revenit la `healthy`.
Nu au fost schimbate configurația nginx globală sau celelalte proiecte VPS.

## Verificări după lansare

- Ambele replici web și workerul rulează digestul și revizia de mai sus,
  cu `runsc-net`, rădăcină numai pentru citire și zero restarturi observate.
- `/healthz` și `/readyz`: HTTP 200; baza de date și Redis raportează `ok`.
- Workerul Celery răspunde la ping.
- `/en/`, `/upload/` și `/admin/login/`: HTTP 200, conținut nou și `no-store`.
- Profilul fără autentificare redirecționează către login; API-ul fără cheie
  returnează 401. Rutele private păstrează `noindex` și `no-store`.
- Scripturile publice `upload.js` și `dashboard.js`, livrate cu nume hash-uite,
  corespund byte cu byte surselor testate.
- Un PDF sintetic, fără date personale, a parcurs prin domeniul public upload
  cu scanare activă → compresie → descărcare PDF valid → descărcare din oglinda
  R2. Documentul și rezultatul de test au fost șterse prin controalele de
  ownership ale aplicației, iar sesiunea anonimă a fost închisă.
- Inspecția limitată a logurilor de după lansare nu a găsit tracebackuri sau
  linii ERROR/CRITICAL. Nu au fost folosite documente ori conturi ale clienților
  drept fixture de test.

## Problemă operațională rămasă

Autentificarea SSH a jobului GitHub Actions este încă defectă:
`ssh: unable to authenticate, attempted methods [none publickey]`.
Producția este actualizată prin lansarea locală verificată; workflow-ul complet
GitHub rămâne marcat eșuat din cauza pasului SSH. Pentru următoarele lansări
complet automate trebuie reparată perechea cheie/cont configurată pentru deploy.

Riscurile și etapele de produs rămase sunt în
[auditul din 16 noiembrie](AUDIT_2026-11-16.md). Acest jurnal documentează
lansarea reviziei de aplicație indicate mai sus; nu adaugă modificări de cod.
